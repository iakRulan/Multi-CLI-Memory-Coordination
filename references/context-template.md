# Task Context 模板

## 使用说明

复制此模板到项目根目录，命名为 `.task-context.md`，然后根据实际任务填写。

---

```markdown
# Task Context: [任务名称]

## 目标
[一句话描述最终要达成什么]

## 背景
[为什么做这件事，相关背景信息，越简洁越好]

## 已完成
- [x] [步骤描述] ([YYYY-MM-DD], [使用的AI工具])
- [x] [步骤描述] ([YYYY-MM-DD], [使用的AI工具])

## 当前卡点
- [ ] [描述当前遇到的问题或阻塞，一句话说清楚]

## 约束条件
- [技术约束]
- [业务约束]
- [时间约束]

## 相关文件
- `[文件路径]` — [一句话说明作用]
- `[文件路径]` — [一句话说明作用]

## 关键决策
- [决策标题]: [描述及原因] ([YYYY-MM-DD])

## 待探索
- [ ] [想法或方向1]
- [ ] [想法或方向2]

---
最后更新: [YYYY-MM-DD HH:MM:SS]
```

---

## 示例

```markdown
# Task Context: 重构用户认证模块

## 目标
将现有基于 Session 的认证迁移到 JWT，支持多设备登录。

## 背景
当前 Session 方案在微服务架构下难以扩展，且不支持移动端。

## 已完成
- [x] 调研 JWT vs Session 方案 (2026-06-20, Claude)
- [x] 确定使用 refresh token + access token 双令牌机制 (2026-06-20, Claude)
- [x] 编写 Token 生成/验证工具类 (2026-06-21, Codex)

## 当前卡点
- [ ] 需要确定 refresh token 的存储方式（Redis vs 数据库）

## 约束条件
- 必须兼容现有用户数据，不能强制重新登录
- 不能使用外部认证服务（如 Auth0）
- 两周内完成上线

## 相关文件
- `./src/auth/jwt_utils.py` — JWT 生成与验证
- `./src/auth/middleware.py` — 认证中间件
- `./docs/auth-migration.md` — 迁移方案文档

## 关键决策
- 双令牌机制: 使用短有效期 access token (15min) + 长有效期 refresh token (7天)，平衡安全与体验 (2026-06-20)
- 不启用黑名单: 依赖 token 过期时间，简化实现 (2026-06-20)

## 待探索
- [ ] 是否需要在 Redis 中存储 refresh token 实现主动失效
- [ ] 多端登录互踢策略

---
最后更新: 2026-06-21 14:30:00
```

---

## 更新 checklist

每次与 AI 交互后，检查是否需要更新：

- [ ] 是否有新的进展需要记录到"已完成"？
- [ ] 当前卡点是否已解决？是否需要更新？
- [ ] 是否做了新的技术决策？是否需要记录到"关键决策"？
- [ ] 是否有新的待探索方向？
- [ ] "最后更新"时间是否已更新？
